# 推理服务与并发设计

## 先分清两种延迟

首 token 延迟决定用户觉得系统"反应快不快"，总延迟决定用户要等多久拿到完整回答。流式输出把总延迟拆成了连续的小块，虽然总时长没变，但感知速度大幅提升，因此面向终端用户的服务几乎都应该用流式。优化首 token 延迟要减少排队和预填充时间，优化总延迟要提升解码吞吐。

## 批处理与并发

推理服务的吞吐来自批处理：把多个请求的预填充和解码合并在一起计算，能显著摊薄显存带宽压力。连续批处理允许在生成过程中动态加入新请求，而不是等整批结束，这对长短请求混合的真实负载尤为重要。同时要限制单请求的最大生成长度，避免个别长请求长时间占用批处理槽位。

## 超时与限流

必须给每个请求设置超时，并且超时要区分排队超时和生成超时，两者的处理策略不同。限流应该按 token 而不是按请求数计，因为不同请求消耗的算力差异极大。GPU 打满时的降级策略要提前设计好：缩短上下文、降低最大输出长度、切到小模型，或者直接拒绝低优先级流量。
