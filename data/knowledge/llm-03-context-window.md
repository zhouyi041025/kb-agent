# 上下文窗口与 KV Cache

## KV Cache 的作用

自回归生成时，每生成一个 token 都要对之前所有 token 做注意力计算。KV Cache 把每一层已经算过的键值对缓存下来，生成新 token 时只计算当前 token 的查询，直接复用历史缓存，把单步计算量从与序列长度的平方相关降到了线性。代价是显存占用随序列长度和并发数线性增长。

## 显存怎么估算

缓存占用正比于层数、注意力头维度、序列长度、批大小和精度字节数。序列长度翻倍，缓存占用翻倍；并发翻倍，占用再翻倍。这就是长上下文服务吞吐会明显下降的原因：显存被缓存占满后，能并发的请求数就变少了。

## 长上下文的两个误区

第一个误区是认为窗口越大越好。窗口变长会带来成本上升、首 token 延迟上升，而且模型对中间位置信息的注意力会衰减，把关键内容放在长上下文中间反而容易被忽略，这就是所谓的"中间迷失"。第二个误区是把检索不到的内容全塞进上下文当作补救，结果引入噪声，既贵又不准。
