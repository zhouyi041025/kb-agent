# Agent 的失败兜底与可观测

## 三类典型失控

最常见的是死循环：模型反复调用同一个工具，或在两个工具之间来回跳。第二种是预算失控：每一步都合理，但步数累积导致 token 成本远超预期。第三种是静默错误：某一环拿到了错误数据却继续往下走，最后给出一本正经的错误结论。

## 兜底手段

设最大步数上限是最基本的一道闸，超过就直接终止并返回已有的中间结果。工具调用要做结果缓存，相同参数重复调用时直接命中缓存，这同时解决了死循环和成本问题。对写操作加人工确认，或者限制为幂等操作。每一步都要能单独超时，不能让一个慢工具拖垮整条链路。

## 可观测性

Agent 排障的难点在于"错在哪一步"不直观。解决办法是把每次执行记录成一条调用链：每一步的输入、输出、耗时、token 消耗和模型决策理由都留痕，并给整条链路一个统一的 trace 标识。有了这条链路，才能回答"这次失败是工具返回错、模型判断错、还是参数拼错"。
