# Function Calling 原理

## 模型怎么选工具

Function Calling 的本质是把工具描述作为结构化输入提供给模型，模型输出一个结构化的调用请求，包含工具名和参数。模型并不是真的在执行函数，它只是根据工具的名称、描述和参数说明来判断哪个工具最匹配当前意图。因此工具描述的质量直接决定了调用准确率。

## 工具描述怎么写

描述里要写清楚三件事：这个工具做什么、什么情况下应该用、参数的含义和取值约束。常见错误是描述过于简短，比如只写"查询数据"，模型无法判断该在什么时候调用它。另一个常见错误是多个工具职责重叠，模型会在两者之间摇摆，调用结果不稳定。职责边界清晰比描述详细更重要。

## 调用失败的兜底

模型可能返回不存在的工具名、缺失必填参数、或参数类型不符。这些必须在服务端校验并给出结构化错误，然后决定是重试、改用其他工具还是直接返回失败。绝不能把未校验的参数直接传给下游系统，尤其是涉及写操作或金额的场景。
